The `.agents/AGENTS.md.map` file is your **single source of truth** for how AGENTS.md and Skills work together. It
answers: "What does the agent do? When? How does it decide?"

Use this template as a starting point for your project.

---

## Template: Complete AGENTS.md.map

```markdown
# AGENTS.md.map - Skill Router Configuration

**Project:** [Your Project Name]
**Last Updated:** [Date]
**Maintainer:** [Your Name]
**Documentation:** See `/AGENTS.md` for global rules

---

## Overview

This file documents how specialized Skills extend the global AGENTS.md instructions.

### What AGENTS.md Provides (Always Loaded)

The root `/AGENTS.md` file provides project-wide rules loaded at every session start:

- **Commands:** Exact executable commands (`npm run dev`, `npm test`, etc.)
- **Boundaries:** Three-tier rules (Always Do / Ask First / Never Do)
- **Code Style:** Naming conventions, type annotations, component structure
- **Testing:** Framework, mocking strategy, coverage thresholds
- **Git Workflow:** Branch naming, commit format, PR process
- **Project Structure:** Directory organization and file purposes
- **Patterns:** Non-obvious architectural decisions explained

**Size:** ~150 lines | **Cost:** Always loaded (~1-2KB)

### What Skills Provide (Loaded On-Demand)

Specialized skills activate only when relevant, providing domain expertise without bloating the global context.

**Size:** ~200-400 lines each | **Cost:** Zero until triggered
```

## Adding a New Skill

When you need a new domain:

### 1. Create the directory

```bash
mkdir -p .agents/skills/[domain-name]/{scripts,references}
touch .agents/skills/[domain-name]/SKILL.md
```

### 2. Write the SKILL.md frontmatter

```yaml
---
name: [ domain-name ]
description: Clear statement of what the skill does, specific trigger phrases,
when to use it. Example: "Optimizes blog content for search engines including
meta tags, structured data, and internal linking. Use when user asks to
'optimize for SEO', 'add meta tags', 'improve search visibility'."
---
```

### 3. Write the instructions

Keep SKILL.md under 400 lines. Use progressive disclosure:

- Main instructions in SKILL.md
- Detailed references in `references/`
- Executable commands in `scripts/`

### 4. Update this AGENTS.md.map

Add your skill to the directory below, including trigger phrases and file structure.

### 5. Commit together

```bash
git add .agents/skills/[domain-name]/
git add .agents/AGENTS.md.map
git commit -m "Add [domain-name] skill"
```

```markdown
## Typical Workflows

### Writing a Blog Post

1. AGENTS.md loads (commands, style, structure)
2. User asks: "Write a post about React"
3. mdx-formatter skill loads (frontmatter, content rules)
4. User asks about SEO
5. seo-optimizer skill loads (meta tags, keywords, linking)
6. Agent formats post following both skill rules

### Debugging a Bug

1. AGENTS.md loads (commands, testing rules)
2. User reports: "Why is the database query failing?"
3. error-handler skill loads (debugging workflow)
4. database skill might load if schema/query issues emerge
5. Agent reproduces error, analyzes logs, suggests fix

### Code Review

1. AGENTS.md loads (code style, boundaries)
2. User asks: "Review my component"
3. ui-components skill loads (accessibility, design)
4. code-review skill loads (quality, security, testing)
5. Agent reviews against both skill checklists
```
