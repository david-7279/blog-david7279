# Security Policy

## Supported Versions

Security updates are provided for the latest version of the project available on the `main` branch.

As this is a personal project, older versions and inactive branches may not receive security fixes.

## Reporting a Vulnerability

If you discover a security vulnerability in this project, please **do not open a public GitHub issue**.

Instead, report it privately by contacting:

**Email:** [david.dev7279@outlook.com](mailto:david.dev7279@outlook.com)

Please include as much relevant information as possible, such as:

* A description of the vulnerability
* Steps to reproduce the issue
* The potential impact
* Affected functionality or files
* Any proof of concept, if available
* Suggested remediation, if applicable

Providing detailed reproduction steps will help with investigation and resolution.

## What to Expect

After receiving a security report:

1. The report will be reviewed and investigated.
2. Additional information may be requested if necessary.
3. The vulnerability will be assessed and, where appropriate, a fix will be prepared.
4. Security fixes may be released through a new commit, pull request, or deployment.

There is no guaranteed response or resolution time, but security reports will be handled as a priority.

## Scope

This policy applies to the source code and functionality maintained in this repository.

Third-party services and infrastructure, including hosting, database, email delivery, and external dependencies, may have their own security policies and reporting procedures.

## Responsible Disclosure

Please allow reasonable time for a vulnerability to be investigated and addressed before publicly disclosing it.

Thank you for helping keep this project and its users secure.
